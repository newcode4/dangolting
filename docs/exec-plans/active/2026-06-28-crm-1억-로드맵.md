## 목표:
단골팅 CRM을 **「아침 5분 · 오늘 할 일 처리 · 3년 뒤에도 규칙 바꿔도 안 깨지는」** 운영 시스템으로 만든다.  
숫자·상태·알림마다 **정의 → UI → 테스트 → 롤백**을 한 묶음으로 설계한다.

## 디자인 · 가독성 · 편의성 원칙

> CRM은 차트 앱이 아니라 **운영자의 아침 체크리스트**다.

### 화면 우선순위 (위 → 아래)
1. **오늘 할 일** — 숫자 + SLA 색 + 클릭 시 해당 신청자
2. **이번 기간 핵심 4칸** — 방문·신청·입금·매칭 (스캔 3초)
3. **전환 흐름** — 어디서 막혔는지
4. **추이·퍼널·테이블** — 원할 때만 펼침

### 타이포 · 숫자
- KPI 숫자: `font-variant-numeric: tabular-nums` (이미 `crm-glance-*` 일부 적용 → 전체 통일)
- 제목 14px / 본문 13px / 보조 11px — **3단계만** (더 늘리지 않음)
- 색: 의미 고정 — 입금 `#d29922`, 매칭 `#58a6ff`, 거절 `#a371f7`, 환불 `#8b949e`, 위험 `#f85149`

### 밀도 · 레이아웃
- PC: 4열 glance · 알림 가로 flex · 기간 1행 (`repeat(4, 1fr)`)
- 모바일 (<768px): glance 2열 · 알림 스택 · 테이블 가로 스크롤
- **한 화면에 primary action 1개** — 탭 전환 최소화

### 편의 (클릭 수)
- 알림 카드 클릭 → **신청자 탭 + 해당 단계 필터** (딥링크)
- 신청자 행 클릭 → 매칭 탭 해당 카드 (Phase 2)
- 기간: 이번 주 / 지난 주 / 이번 달 / 전체 — **4버튼 고정**

### 접근성
- 색만으로 상태 구분 금지 — 라벨·숫자 항상 병기
- SLA 위험: 색 + `48h+` 텍스트

## stop rule

- diff 500줄 초과 → 해당 M을 M-a / M-b로 분할
- E2E 2개 이상 실패 → **즉시 rollback**, 원인 bug-card 작성 후 재개
- Phase N gate FAIL → Phase N+1 착수 금지
- 「예쁜 차트」 요청이 M3(큐)보다 앞서면 **큐 우선**

## rollback

| Phase | kill switch | revert scope |
|-------|-------------|--------------|
| 1 | `CRM_QUEUE_ENABLED=false` (env 또는 session) | `crm_truth`/`crm_queue` import 제거 → 기존 `build_crm_snapshot` 직접 |
| 2 | 타임라인 expander 기본 닫힘 | `crm_timeline.py` + UI 블록 revert |
| 3 | audit 비활성 | `audit.jsonl` write hook 제거 |

**공통 kill switch:** CRM 탭만 숨기고 매칭 탭 계속 (`render_crm_tab` early return)
